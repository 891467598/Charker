# win22 MIOT帧格式修正

在用户固件2.1.2_0073上实测，明文头结构为：长度(1字节)、0x20、序号(小端2字节)、消息标志(1字节)、属性数量(1字节)，随后是属性列表。初始化帧为5字节、标志0xf0，无属性数量。长度字段应按实际字节数填写，不应当作固定操作码。

| 标志 | 类型 |
| --- | --- |
| 0x02 | 查询请求 |
| 0x03 | 查询响应，每个属性包含状态码 |
| 0x00 | 设置请求 |
| 0x01 | 设置响应 |
| 0x04 | 主动上报，属性不包含状态码 |

本次发现的实际响应包括：四口快照50字节（0x32）、四口及8项设置快照114字节（0x72）、单端口上报15字节（0x0f）。旧版只接受0x93/0x1c/0x0e等固定首字节，因而把114字节的有效应答忽略，最终超时。

win22按长度、标志和序号校验、匹配响应；不让相同序号的上报误完成查询。GET和SET编码同时计算实际长度，多属性上报可独立解析。新增测试涵盖1—21项GET请求、不同值宽度SET、不同长度响应、两字节属性与同长通知的区分、114字节多片回复中插入相同序号的24字节通知。

测试报告只记录消息长度、标志、序号和连接阶段，不包含Token、随机数、HMAC、MAC地址或原始载荷。本次实机验证仅执行认证及读取，没有写入端口开关、模式或屏幕设置。
